# Default Orchestrator Router Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the project `default` agent explicitly plan, selectively delegate, aggregate, and verify work as the permanent orchestration entrypoint.

**Architecture:** Codex retains `default` as its root-agent identifier, while the legacy compatibility source gives that profile explicit orchestrator-routing instructions. The Codex TOML is then regenerated from the source definition; `settings.json` remains the legacy default-agent selector pointing to `orchestrator`.

**Tech Stack:** JSON agent definitions, Python `pytest`, Python synchronization scripts, generated TOML.

## Global Constraints

- Keep the `default` agent identifier; Codex may continue to render it as `Main [default]`.
- Keep `orchestrator` as the named orchestration role and do not rename or delete legacy agents.
- Treat `.agents/agents/default/agent.json` as the source for `.codex/agents/default.toml`; never manually edit generated TOML.
- Do not alter `settings.json` because its `default_agent` is already `orchestrator`.
- Preserve unrelated dirty-worktree changes.
