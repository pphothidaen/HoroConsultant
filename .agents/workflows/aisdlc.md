# AI SDLC Workflow Pipeline & Token Cost Optimization Guide

This workflow defines the end-to-end multi-agent execution pipeline for the **HoroConsultant** project on Antigravity CLI.

---

## 🔄 SDLC Lifecycle Diagram

```
User Order
   │
   ▼
1. 🧠 Orchestrator (Gemini 3.6 Flash - High Effort)
   │  └─ Analyzes Requirement & Writes Plan to /plans/plan.md
   │
   ▼
2. 💻 Senior Developer (Gemini 3.6 Flash / 3.5 Flash-Lite)
   │  └─ Implements Code & Writes Module Docs
   │
   ▼
3. 🧪 QA Tester (Gemini 3.5 Flash-Lite)
   │  └─ Generates Test Cases & Runs `pytest`
   │      ├─ [FAIL] ──> Generates Bug Report ──> Returns to Developer (Loop)
   │      └─ [PASS] ──> Reports 100% Success to Orchestrator
   ▼
4. 🚀 DevOps & Release (Gemini 3.6 Flash Standard)
   │  └─ Audits .env, Dependencies, Docker, and Release Readiness
   │
   ▼
5. 🧠 Orchestrator (Final Code Review & Summary)
   │  └─ Generates Final Delivery Summary for User
   ▼
User Delivery Complete
```

## 📋 Step-by-Step Execution Phases

### Phase 1: Planning & Blueprinting (Orchestrator)
- **Model**: `Gemini 3.6 Flash` (Thinking Effort: High)
- **Input**: User requirement or request.
- **Action**:
  1. Analyze scope, architecture requirements, and security constraints.
  2. **Kaggle Sync Pre-Check**: Run `python3 scripts/kaggle_notebook_manager.py --status` (and `--pull` if updated) to sync latest kernel version/outputs before starting.
  3. Create or update plan document at `/plans/plan.md` (or Antigravity implementation plan).
  4. Deconstruct job into specific sub-tasks for `developer`, `qa_tester`, and `devops`.

### Phase 2: Feature Implementation (Developer)
- **Model**: `Gemini 3.6 Flash` (Standard Mode) / `Gemini 3.5 Flash-Lite`
- **Input**: Sub-task specs from Orchestrator.
- **Action**:
  1. Write/modify source code files under `project/` or `rust_core/`.
  2. Write inline comments and module README.
  3. Submit completed code back to Orchestrator.

### Phase 3: Quality Assurance & Testing (QA Tester)
- **Model**: `Gemini 3.5 Flash-Lite` (Lowest cost, test execution focus)
- **Input**: Source code generated by Developer.
- **Action**:
  1. Generate Unit and Integration test cases in `tests/`.
  2. Execute test suite:
     ```bash
     PYTHONIOENCODING=utf-8:surrogateescape PYTHONUTF8=1 python3 -m pytest -v
     ```
  3. **Handling Results**:
     - **FAIL**: Write Bug/Issue Report with exact traceback and root cause analysis. Send back to Orchestrator to bounce task to Developer.
     - **PASS**: Report 100% pass status to Orchestrator.

### Phase 4: Environment & Release Verification (DevOps)
- **Model**: `Gemini 3.6 Flash` (Standard Mode)
- **Input**: Fully tested code approved by QA.
- **Action**:
  1. Check `.env.example`, `requirements.txt`, `Dockerfile`, `docker-compose.yml`.
  2. Verify pip flags (`-q --progress-bar off --prefer-binary`) and dependency compatibility matrix.
  3. Validate release readiness and report to Orchestrator.

### Phase 5: Final Review & Delivery (Orchestrator)
- **Model**: `Gemini 3.6 Flash` (Thinking Effort: High)
- **Input**: Pass reports from QA and DevOps.
- **Action**:
  1. Conduct final code review and security audit.
  2. Synthesize results and deliver comprehensive summary report to User.
