# KAN-184: Dev Branch Guard Soft-Exemption for Test Provenance

## Goal

Add a soft-guard to `scripts/test_provenance_guard.py` that skips full provenance verification on dev branches (`feat/*`, `fix/*`, `wip/*`, `experiment/*`, `review/*`, `draft/*`, `temp/*`) while keeping protected branches (`main`, `master`, `release/*`) fully enforced.

## Current Context / Assumptions

- **Branch:** `main` (behind origin/main by 20 commits — pull before starting)
- **Modified file:** `scripts/test_provenance_guard.py` already has two config constants added at the top:
  - `PROTECTED_BRANCHES = frozenset({"main", "master", "release/*"})`
  - `DEV_BRANCH_PATTERNS = ("feat/*", "fix/*", "wip/*", "experiment/*", "review/*", "draft/*", "temp/*")`
- **Test file exists:** `tests/test_dev_branch_guard.py` — imports `_dev_branch_skip_provenance` and `_get_current_branch` from the guard module. Currently fails because those functions don't exist yet.
- **No helper functions exist:** `_get_current_branch()`, `_is_protected_branch()`, `_dev_branch_skip_provenance()` are not implemented.
- **No soft-guard logic in `verify_pr()`:** The `verify_pr()` command always runs full provenance checks regardless of branch.
- **TDD pattern established:** The repo uses a strict test-first cycle — test commit (test file + manifest, NO source changes) → source commit (feature code with `Test-Baseline: <test_commit_sha>` trailer).
- **Pre-commit hook:** `.githooks/pre-commit` runs `test_provenance_guard.py staged` and rejects mixed source+test commits.
- **CI:** `.github/workflows/ci.yml` runs `test_provenance_guard.py verify-pr` on PRs to `main`/`master`.

## Architecture / Proposed Approach

The guard already has the config constants. We need three helper functions that use `fnmatch` to match branch names against the patterns, then a soft-guard check in `verify_pr()` that short-circuits to PASSED when on a dev branch. The `verify()` command (single-commit) is NOT affected — only `verify-pr` (the CI entry point) gets the soft-guard, because dev branches are expected to have incomplete provenance until they're ready for PR.

```python
import fnmatch


def _get_current_branch(repo: Path) -> str:
    """Return the current branch name for the given repo path."""
    result = subprocess.run(
        ["git", "rev-parse", "--abbrev-ref", "HEAD"],
        cwd=repo,
        capture_output=True,
        text=True,
        check=True,
    )
    return result.stdout.strip()


def _is_protected_branch(branch: str) -> bool:
    """Return True if the branch matches a protected pattern."""
    return any(
        fnmatch.fnmatch(branch, pattern)
        for pattern in PROTECTED_BRANCHES
    )


def _dev_branch_skip_provenance(repo: Path) -> bool:
    """Return True if the current branch is a dev branch that should skip full provenance.

    Dev branches (feat/*, fix/*, etc.) skip provenance verification.
    Protected branches (main, master, release/*) never skip.
    """
    branch = _get_current_branch(repo)
    if _is_protected_branch(branch):
        return False
    return any(
        fnmatch.fnmatch(branch, pattern)
        for pattern in DEV_BRANCH_PATTERNS
    )
```

**Note:** `subprocess` and `Path` are already imported at the top of the file. `fnmatch` is a new import — add it to the existing import block.

## Risks, Tradeoffs, and Open Questions

### Risks
- **Pre-commit hook rejection:** If the test commit accidentally includes source changes, the hook will reject it. Mitigation: `git add` only the test file in Task 3.
- **Argument name mismatch in `verify_pr()`:** The soft-guard code assumes specific argument names. Mitigation: Read `verify_pr()` before writing the patch to confirm exact names.
- **fnmatch vs regex:** `fnmatch` uses Unix shell-style wildcards (`*` matches everything). This is correct for branch name patterns like `feat/*`. Do NOT use `startswith` — it wouldn't handle `release/*` correctly.

### Tradeoffs
- **Soft-guard only on `verify-pr`:** The `verify()` command (single-commit) is NOT given a soft-guard. This is intentional — `verify()` is used in pre-commit hooks where we always want full enforcement. Only `verify-pr` (CI entry point) gets the skip.
- **No audit trail for skipped checks:** The skip is reported in the `notes` field of the JSON report, but there's no persistent log of which commits were skipped. This is acceptable for now — the PR merge to main will still be fully verified.

### Open Questions
- Should `verify()` also get a soft-guard? (Current decision: NO — pre-commit should always enforce.)
- Should there be a `--force-provenance` flag to override the skip on dev branches? (Current decision: NO — YAGNI.)
- Should the skip be logged to a file for audit purposes? (Current decision: NO — the JSON report notes field is sufficient.)
